# Task Inbox · 样式规范

> 这份文件是 `board.html` 里所有 CSS 的**唯一裁判**。
> 改样式前先读这里；改完跑 `node style-audit.mjs`，红了就说明跑偏了。
>
> 为什么不拆成 CSS 文件：这个页面要能单文件双击打开、也要能被 Alma 插件
> 直接当静态资源 serve，拆文件会多一条"路径找不到"的故障线。所以规范靠
> **文档 + 自动检查**约束，而不是靠物理拆分。

---

## 一、三层材质模型（最重要的规则）

任何新增界面元素，先判断它属于哪一层，再决定能不能用玻璃。

| 层 | 谁在这一层 | 允许的材质 |
|---|---|---|
| **内容层** | 任务标题、标签、正文、表格、图表、消息气泡、表单值 | **必须不透明**。白底或深色实底，永远不做 `backdrop-filter` |
| **结构层** | 侧栏、看板列、卡片外壳、工具栏、抽屉壳、弹窗壳 | 玻璃（半透明 + 模糊）、拟态（内高光/内阴影） |
| **装饰层** | 斜向反光条、网格、扫描光斑、拉丝纹理 | 纯装饰，`pointer-events:none`，`opacity ≤ .9` |

**判断口诀**：字要被人读的地方，不许是玻璃。

原因不是审美，是可读性：`backdrop-filter` 让背景随滚动不断变化，
文字对比度就跟着抖。看板卡片里那行「P2 常规 · 诺华-数据分析平台」是
12px 小字，压在玻璃上会时清楚时不清楚。

## 二、颜色

### 唯一来源：`:root`

CSS 里**除 `:root` 之外不允许写死颜色**。需要新色就先在 `:root` 加变量。

| 变量 | 值 | 用途 |
|---|---|---|
| `--silver-00/50/100/200/300` | `#F7F8F8` → `#B7BFC2` | 银白背景梯队 |
| `--slate-700` / `--ink` | `#566168` / `#151A1E` | 次要文字 / 正文 |
| `--orange` | `#FA4616` | **只做点缀**：状态点、左边条、图标、描边 |
| `--orange-cta` | `#C93610` | 白字按钮 / 白字徽章底色 |
| `--orange-cta-hi/deep` | `#D84414` / `#A83209` | 主按钮渐变的两端与描边 |
| `--orange-soft` | `#FFE5DC` | 选中态浅底 |
| `--p0`…`--p4` | 见 `:root` | 优先级色 |
| `--todo/--doing/--done` | 三态色 | 看板列圆点、数字徽章 |
| `--text-1`…`--text-4` | `#151A1E` → `#7f8b8f` | 文字四级：正文 / 次要 / 说明 / 最弱 |
| `--side-top/mid/bot` | `#f0f3f3` → `#dde3e5` | 侧栏底色三段（提亮过，见下） |

### 文字只有四级

灰不要随手调。以前这个文件里有 106 种写死的颜色，其中十来种
（`#7b878b` `#8a969a` `#94a0a4` `#8b9599` `#7c898d` `#6c767a` …）
视觉上几乎一样，都是"说明文字"。现在收敛成四级：

- `--text-1` 正文、标题
- `--text-2` 次要正文（表单标签、帮助文字）
- `--text-3` 说明、标签、面包屑
- `--text-4` 占位符、时间戳、计数

需要更浅的字，先问是不是该换级，而不是加一个新灰。

### 字号下限：10px

侧栏原来散着 8.5 / 9 / 9.5px 若干档（品牌副标、section 标题、计数、脚注）。
在 1080p 的 100% 缩放下，8.5px 的中文基本是"糊成一团"。
现在统一：**正文最小 10px**，标题类（`h1`）单独一档，其余都在 10px 以上。

```css
/* 允许的档位：10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14.5 / 21 */
```

小于 10px 只允许出现在**纯装饰**上（箭头 `▾`、图标内的字形），
不允许承载任何信息。

### 灰要压在什么底上，是按对比度算出来的

`--text-3` / `--text-4` 的取值不能只看白底。侧栏那块是银灰渐变，
最暗端原来到 `#cbd2d4`，同一档 `--text-3` 只有 **2.41:1** ——
"未分配"、项目计数、section 标题在侧栏里其实读不清。

| 底 | 旧 `--text-3` 3.70(Card) | 新 `--text-3` `#667277` |
|---|---|---|
| 卡片白 `#ffffff` | 3.70 | 4.95 |
| 看板列 `#eef2f3` | 3.28 | 4.40 |
| 侧栏最暗 `#dde3e5` | 2.41(原 #cbd2d4) | 3.82 |
| 侧栏最亮 `#f0f3f3` | 3.13 | 4.44 |

所以侧栏底色也一并提亮（`--side-*`）。**加新的灰底时先算一遍**，
别让同一档字在不同容器里忽明忽暗。

Lint（`style-audit.mjs` 里没有，需要时手动跑）：

```bash
node -e 'const L=h=>{h=h.replace("#","");const v=[0,2,4].map(i=>parseInt(h.slice(i,i+2),16)/255).map(c=>c<=.03928?c/12.92:((c+.055)/1.055)**2.4);return .2126*v[0]+.7152*v[1]+.0722*v[2]};const r=(a,b)=>{const x=L(a),y=L(b);return ((x>y?x:y)+.05)/((x>y?y:x)+.05)};console.log(r(process.argv[1],process.argv[2]).toFixed(2))' "#667277" "#dde3e5"'
```

### 硬规则：白字必须配深橙

`--orange` (#FA4616) 配白字对比度只有 **3.53:1**，达不到 WCAG AA 的 4.5:1。
所以：

- 白字按钮 / 白字徽章 → `--orange-cta` (#C93610) 起步
- `--orange` 只能用于**非文字**或**深色文字压在上面**的场合

改按钮颜色时如果想让"更亮一点"，先想想白字还读不读得清。

## 三、控件：一套底，只写差量

所有按钮的**形状、材质、描边、过渡**在 `board.html` 的
「按钮：整个页面只有这一套底」注释块里定义一次。
组件选择器只允许写**差量**（尺寸、字号、内边距、宽度、图标大小）。

```
.icon-btn, .rail-toggle, .sys-btn,
.mini, .mini-btn, .flt-reset,
.dlg button, .dr-row button, .pick-bar button, .dock .go
```

新增按钮 = 把选择器**加进这个列表**，不要复制粘贴一份渐变和阴影。

### 四种按钮语义

| 类 | 长什么样 | 什么时候用 |
|---|---|---|
| 默认 | 凸起白瓷，1px 描边 | 普通动作（取消、清空、选择） |
| `.primary` | 深橙实心 + 白字 | **一屏只能有一个**，主动作（存下、发送、保存） |
| `.mini` | 虚线边框、无底 | 增量动作（+ 新建项目、+ 添加目录） |
| `.rm` | 无边框无底，只有字形 | 就地删除（目录行） |
| `.btn--danger` | 橙字、无实底 | 危险动作（删除项目） |

**贴在别的东西上的按钮不挂总则**：缩略图右上角的 ✕（`.thumb button`）、
输入框里的箭头（`.combo-toggle`）、下拉触发器（`.sel-btn`）——
它们没有独立的白瓷底，硬挂总则会变成一块浮在图片上的白方块。
`style-audit.mjs` 的白名单里列了这几个。

不要自创 `.btn--primary` / `.btn--quiet` 这类新名字——主动作已经在用
`.primary`，增量动作已经在用 `.mini`，再加同义类名只会让人不知道该抄哪个。

### 输入框同理

`.dock textarea`、`.dr-foot textarea`、`.dlg select`、`.dlg input`、
`.dr-fields select`、`.pick-bar input`、`.dir-row input` 共享一条
「输入框：内凹材质」规则。组件里只写宽高和内边距。

**凸起 = 按钮，内凹 = 输入框。** 这是拟态材质的基本语法，别混用：
把输入框做成凸起的白卡片，人会以为它能点。

### 下拉框：两档尺寸，一份菜单

原生 `<select>` 的下拉层是浏览器的，CSS 改不到。所以统一用
`.sel` + `.sel-native`：原生 `select` 留作状态源（视觉隐藏），
上面盖自定义按钮和玻璃菜单。**不要**为了省事只给原生 select 加个箭头
就交付——弹出层的灰三角和蓝底会破坏整个页面的材质一致性。

| 档位 | 类 | 尺寸 | 用在哪 |
|---|---|---|---|
| 紧凑 | `.sel` | 26px，无边框，选中时橘底高亮 | 筛选条（融进工具条） |
| 表单 | `.sel` + `.sel--field` | 36px，独立描边 | 弹窗里的字段 |
| 行内 | `.sel` + `.sel--inline` | 32px，窄 | 目录行的「主要 / 副」 |

用法：给原生 select 加 `class="sel-native"`，想要哪档再加
`data-sel="field"` 或 `data-sel="inline"`，`buildSels()` 会自动包一层。

**只有紧凑档才有「已选中」橘色高亮**——表单档和行内档永远有值，
高亮会让整个字段看起来像报错。

`buildSels(root = document)` 是幂等的（已包过的跳过）。动态生成、**还没
插进文档**的片段必须传自己的容器：`buildSels(wrap)`。传 `document` 会
因为元素还不在文档里而找不到——目录行就踩过这个坑。

同时它只往 `document` 挂一次全局监听（`buildSels.bound`），
否则每次生成目录行都会多挂一对 click/keydown。

### 可搜索组合框（模型选择）

模型有几十个，不能做成纯下拉。用 `.combo`：一个看起来像输入框的
框 + 右侧箭头 + 可过滤的菜单。它允许**自由输入**（清单没拉到时也能手填），
输入即过滤，`↑↓` 选、`Enter` 确认、`Esc` 收起。

判断标准：**选项超过 12 个，就该用组合框而不是下拉**。

### 复选框

不要用浏览器原生 `checkbox`（那个蓝色/白色方块和整页青灰调完全不搭）。
用 `.chk`：

```html
<label class="chk">
  <input type="checkbox" id="x">
  <span class="box" aria-hidden="true"></span>
  <span class="chk-text">文案</span>
</label>
```

原生 input 被视觉隐藏（`opacity:0`），`.box` 是画出来的方块，
选中时填充深橙 + 白勾，`focus-visible` 有焦点环，读屏仍然读到原生 input。

## 四、几何与排布

- 圆角：`--radius-sm 9px`（控件）、`--radius-md 17px`（面板）、`--radius-lg 25px`（弹窗）
- 间距：4 的倍数，常用 6 / 9 / 12 / 16 / 24
- 卡片 meta 行**固定 18px 高 + `nowrap`**：卡片高度只能由标题行数决定，
  不能因为标签数量或窗口宽度变化而抖
- 阴影只许用 `--shadow-1/2/3`，不要临时写 `0 4px 9px rgba(...)`
- 滚动条在 `*` 上统一压细（10px、半透明灰、圆角、无轨道底色）。
  Windows 默认那条灰槽跟这套银白材质完全不搭，别让某个容器单独用原生样式

### 侧栏三段：头固定 / 中段滚动 / 底固定

```
.sidebar          display:flex column; overflow:hidden     ← 自己不滚
  ├─ .brand       flex:0 0 auto                            ← 品牌，钉住
  ├─ .side-scroll flex:1 min-height:0 overflow-y:auto        ← 唯一滚动的地方
  │    ├─ status 菜单
  │    └─ projects 菜单（含标题右侧的 +）
  ├─ .sidebar-bottom flex:0 0 auto                          ← 状态条 + 齿轮，钉住
  └─ .sidebar-foot                                          ← 数据规模，钉住
```

规则：

- **只有中间那段滚**。整条侧栏 `overflow:auto` 的写法会让"标题+底部"跟着
  项目数量一起被推走 —— 项目一多，齿轮和设置就滚出屏幕了。
- 中段必须写 `min-height:0`，否则 flex 子项按内容高度撑开，`overflow:auto`
  不生效（和第八节第 5 条是同一个坑）。
- 滚动条压在 4px 的左右留白里（`margin:0 -4px; padding:0 4px`），
  不让它挤窄行宽、也不让行右侧被截。

### 底部状态条只留一条

原来左下角是 150px 高的 `.systembox`：标题、大号文案、模型名、七段进度条、
整行"设置"按钮。其中「6 待办 · 2 进行中」和上方导航行里的数字是**同一份
数据**，进度条也就两段亮着。现在压成一条 `.sysbar`：状态灯 + 一句话 + 22px
齿轮。侧栏因此多出约 110px 给项目列表。

同类判断标准：**同一个数字在同一个面板里出现两次，就是一处冗余**，
删掉一次不会丢信息。

### 抽屉的两栏：宽度只有一个来源

```
.drawer.doc-on  width = min(var(--dr-wide-w), 96vw)
  ├─ .dr-pane   width = var(--dr-pane-w)     ← 左栏（详情 + 对话）
  ├─ .dr-split  width 11px                   ← 可拖
  └─ .dr-doc    flex 1                       ← 预览栏，吃剩下的全部
```

- **不要给预览栏单独设宽度**。它 = 抽屉宽 − 左栏 − 分隔条，写死第二处
  就会出现"改了左栏、右栏没跟上"的错位。
- `--dr-pane-w` 由 JS 写（拖动时实时写、松手存 `localStorage`）；
  `--dr-wide-w` 由 `drDocFit()` 按视口重算。
- 视口 < 1080px 不并排：切成 `.doc-full`，`.dr-pane` 隐藏、`.dr-doc` 铺满。
  理由不是省事 —— 两栏各剩 400 时，正文和对话都难读，比"看不到对话"更糟。
- 预览栏是**内容层**（读字的地方），底色用不透明的 `--ctl-inset`，
  不能跟着抽屉一起做玻璃。

## 五、z-index 分层

层叠顺序是有语义的，不要随便加数字：

| 值 | 谁 |
|---|---|
| 1 | 看板滚动区、看板列内部（`.col` / `.col-body` 里的相对定位层） |
| 2 | 底栏收起条 `.dock-stub` |
| 3 | 顶栏 `.topbar`、底栏 `.dock` |
| 5 | 看板头部 `header.top`（**必须高于 1**，否则筛选下拉被看板盖住） |
| 60 | 下拉菜单 `.sel-menu` |
| 70 / 71 | 抽屉遮罩 / 抽屉 |
| 72 | 项目选择浮层 `.picker`（**必须高于抽屉 71** —— 从抽屉里点「选项目」徽章也要看得见） |
| 80 | toast |
| 90 | 拖拽放置层 |
| 95 | 顶部横幅 `.boot-bar`（连不上服务 / 后端是旧版本） |
| 99 | 图片灯箱 |

新增浮层先在这里插一行，再写 CSS。`style-audit.mjs` 会拦下表外的数值。

## 六、必须做的降级

任何用了 `backdrop-filter` 的地方，都要在文件末尾那三段查询里登记：

```css
@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) { … }
@media (prefers-reduced-transparency: reduce) { … }
@media (prefers-reduced-motion: reduce) { … }
```

漏登记的后果：老浏览器或开了"降低透明度"的用户看到一片糊的半透明面板，
字看不清但也不知道为什么。

## 七、命名

- **已有类名不动**（`.col`、`.card`、`.dr-*`、`.sel-*` 等已被 JS 引用）
- 新类名按「块-元素」两段式：`.sel-menu`、`.card-meta`。不搞 BEM 三段
- JS 只切这四个状态类：`.on` / `.open` / `.active` / `.hot`。
  新加状态必须同步改这份文档和 `style-audit.mjs` 的白名单

## 八、已知的坑（踩过一次就够了）

1. **`background` 简写会重置 `background-image`**
   `.dr-fields select` 要放自定义箭头（`background-image`）。
   如果通用的输入框规则用 `background: linear-gradient(...)` 简写，
   会把箭头一起冲掉。所以输入框底色用**纯色变量** `--ctl-inset`，
   不用渐变。

2. **`header.top` 的 z-index 曾经是 1**
   和 `.board-area` 同级，导致筛选下拉弹出来被整个看板盖住。
   现在固定 5。

3. **HTTP 请求体不能按分片 `toString()`**
   `server.mjs` 的 `readBody` 曾经是 `buf += chunk`，中文被切在两个 TCP
   分片之间就变 `\uFFFD`，库里真的写出过一个叫「Ĭ��」的项目。
   现在先 `Buffer.concat` 再整体解码。

4. **`transition: all` 别用在会被 JS 改尺寸的元素上**
   卡片 hover 位移用 `transform`，不要用 `top/left`，否则拖动时掉帧。

5. **flex 容器里的子项会被压扁，`overflow:auto` 不报错但滚不动**
   `.dr-detail` 是 `display:flex; flex-direction:column`，`.sect` 作为
   flex 子项默认 `flex-shrink:1`，被压进容器高度以内，再被自己的
   `overflow:hidden` 裁掉 —— `scrollHeight` 永远等于 `clientHeight`，
   滚动条不出现、滚轮也转不动，内容**静默消失**。
   实测：946px 的需求只露出 281px，用户只能看到三分之一。

   修法不是加 `overflow:visible`（那会把卡片撑出抽屉），而是
   **让子项不参与收缩**：

   ```css
   .dr-detail > .sect{flex:0 0 auto}   /* 内容有多高就多高，容器自己滚 */
   ```

   自检方法：`el.scrollHeight > el.clientHeight` 必须是 true。
   如果两者相等而你确信内容超了，先查父级是不是 flex。

6. **动态生成的自定义控件，`buildSels()` 之后必须 `selSync()`**
   前者只负责"套壳"，不回填显示值。只调 `buildSels` 的话三个下拉全是
   空白，要等用户随便点开一个（`pickSel → selSync`）才一起亮起来。
   `drRenderHead()` 就是漏了这一行。**同一个坑在目录行又犯了一次**
   （`dirRow()`），症状更隐蔽：按钮上有文字、点开菜单却是空的 ——
   用户的原话是"点开什么也看不到"。

7. **外框写 `width:100%`，里面的表格写 `min-width` → 表格从框里漏出去**
   `.tbl-wrap{width:100%}` + `.tbl{min-width:1040px}`：表格按内容撑到
   1107px，外框只有 1100px，右边那一列就压在白框外头，还带一条自己的
   边框 —— 看起来就是"表头和表格样式打架"。
   外框宽度必须跟着内容走：**`.tbl-wrap{width:max-content;min-width:100%}`**，
   `min-width` 挪到 `.tbl` 上。横向滚动交给外层 `.board-scroll`，
   别让 `.tbl-wrap` 自己变成滚动容器（那会杀掉 sticky 表头，见第 2 条的同类问题）。

7b. **圆角只有一个来源**
   表格外框 `.tbl-wrap` 有 `border-radius:14px`，表头 `th` 也各自圆了 13px。
   滚动时行是方形、由外框按 14 裁；表头按 13 圆 —— 两个弧差 1px，
   接缝上就露出一条月牙形的白角。**文字上看不出差 1px，接缝上却很明显。**

   规则：一个圆角只能有一个半径来源。要么让外层 `overflow:clip` 裁，
   要么让内层 `border-radius` 跟外层**写成同一个数值**。别写 `inherit` ——
   `th` 的父元素是 `<tr>`，那上面是 0，`inherit` 等于把圆角抹掉。

   顺带：`overflow:clip` 与 `overflow:hidden` 的区别在这里是决定性的 ——
   `hidden` 会让元素变成滚动容器，里面的 sticky 表头就再也不粘。

8. **同一个属性在"一行 flex"里同时要长要短，一定会溢出**
   目录行原来是「路径 + 选目录 + 说明 + 主副 + 删除」一行排开，
   最小宽度 430px，而弹窗可用宽只有 394px → 底部冒出横向滚动条。
   flex 不会报错，它只会静默地撑开父容器。**拆成两行**比压缩每个
   控件的 `min-width` 更可靠：路径本来就该独占一行。
